# Outcome

为已有的 Python 与 pytest 接口自动化项目建立经过确认、可追溯且不含固定技术栈假设的 Tide 项目画像与项目专属规则。

## Routing

- 初始化当前已有项目时，执行 `workflows/§01-initialize.md`。
- 需要读取当前项目之外的本地源码时，先逐个确认目录与用途，再执行同一工作流的额外源码分支。
- 新建测试工程、处理 HAR、生成或执行测试时停止；这些任务不属于本 Skill。
- 未发现 Python 与 pytest 的明确证据时停止，不创建固定脚手架或猜测项目约定。

## Steps

1. 建立只读事实
   - 完整读取 `workflows/§01-initialize.md`，执行项目事实扫描。
   - 并行委派项目扫描与测试资产扫描，所有结论标注证据来源。
   - 完成条件：已确认目标项目属于已有 Python 与 pytest 项目，额外源码范围均已单独授权。

2. 形成初始化计划
   - 根据扫描事实生成项目画像和项目专属规则候选稿。
   - 委派规则审查，修复问题并复审，直到结论通过。
   - 使用计划绑定脚本生成包含内容摘要和目标清单的 JSON 计划。
   - 完成条件：计划可复现，且没有固定代码风格、固定技术栈、行业假设或模板内容。

3. 请求写入确认
   - 展示项目画像摘要、规则文件清单、证据和计划摘要（即唯一计划摘要值）。
   - 用户修改范围时重新生成并审查计划；用户取消时保持项目不变。
   - 完成条件：用户明确确认当前计划摘要值。

4. 原子初始化
   - 将确认的计划摘要交给写入脚本。
   - 只创建 `.tide/project-profile.json` 与 `.tide/rules/`；出现既有 `.tide/`、路径替换或摘要漂移时失败关闭。
   - 完成条件：写入脚本返回成功，重新读取的文件摘要与确认计划一致。

## Delivery

- 报告项目画像、动态生成的规则文件、证据来源和实际写入路径。
- 分别说明已验证、未验证和阻塞内容；脚本退出成功不替代规则语义审查。
- 用户取消、项目不受支持或安全检查失败时，说明停止原因，并确认没有写入目标项目。

## Guardrails

- 当前项目之外的每个本地源码目录都必须由用户逐项授权；所有源码只读，不执行网络或 Git 操作。
- 不读取凭据及原始请求或响应正文；可以按需只读已授权源码，但不得保存源码正文或绝对目录。项目画像仅保存相对路径、逻辑标签和证据摘要。
- 写入确认只授权当前计划摘要对应的 `.tide/` 初始化，不授权修改已有源码、测试、配置、依赖或仓库状态。
- `.tide/` 已存在、目标路径经过符号链接、输入发生漂移或规则审查未通过时停止，不覆盖、不合并、不绕过检查。

## References

- 初始化已有项目时，完整读取 `workflows/§01-initialize.md`。
- 工作流只通过 `prompts/project-scanner.agent.md`、`prompts/test-assets-scanner.agent.md` 与 `prompts/rule-reviewer.agent.md` 委派对应角色。
- 只读事实扫描执行 `scripts/scan_project.py`。
- 规则审查通过后执行 `scripts/bind_init_plan.py`，用户确认计划摘要后执行 `scripts/apply_init_plan.py`。
- 成功、取消或失败后均执行 `scripts/cleanup_temp.py` 清理本次系统临时专用目录。
