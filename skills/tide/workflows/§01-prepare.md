# 建立安全输入

## 阶段 1：验证项目状态

1. 确认当前目录是用户指定的目标项目根目录。
2. 读取 `.tide/project-profile.json`，验证其中已确认 Python 版本、pytest 证据、现有测试目录、pytest runner、环境和来源摘要。runner 未确认不阻断只读分析与生成，但必须阻断真实执行。
3. 完整读取 `rules/security-and-privacy.md`。
4. 未完成初始化、画像结构无效或目标不是已有 Python 与 pytest 项目时停止，提示先执行 `init-tide`；不得自行创建固定工程。

## 阶段 2：确认读取范围

1. 用户必须在当前交互中明确提供本地 HAR 文件路径。未提供时只请求路径并停止；不得搜索、枚举、猜测或自动选择 HAR。
2. 本次分析只读取用户给出的 HAR、当前项目根目录内文件、已确认画像和项目规则。画像中的额外源码逻辑标签不是文件系统路径，不解析、不猜测也不读取项目外目录；需要新的项目外源码证据时，先结束本次运行并重新执行初始化读取范围确认。
3. 不执行 `clone`、`pull`、`checkout` 或其他 Git 操作。
4. 不要求必须有源码。没有源码时，只能使用脱敏 HAR、已确认画像、项目规则和用户确认事实，降低无法证明的断言层级。

## 阶段 3：生成脱敏摘要

先从当前 Skill 的 `SKILL.md` 位置解析 Skill 根目录，执行临时目录脚本，并把其唯一输出的绝对路径作为 `<system-temp>`；不得自行选择、拼接或创建临时目录。临时路径边界由脚本校验，不得把目标项目根目录误当成 Skill 根目录：

```bash
python3 <Skill根目录>/scripts/cleanup_temp.py --create
python3 <Skill根目录>/scripts/sanitize_har.py <har-file> --output <system-temp>/har-summary.json
python3 <Skill根目录>/scripts/sanitize_har.py --validate-summary <system-temp>/har-summary.json
```

任何角色都不能读取 `<har-file>`。任一脚本失败时只报告其安全诊断，不复制原始内容。两个命令均成功后，只采用严格校验脚本接受的摘要：

- 摘要格式版本、条目数量和 SHA-256 已生成；
- 摘要不包含原始主机、路径段值、请求值、响应值、Cookie 或认证值；
- 摘要路径位于系统临时目录，不在目标项目内。

## 阶段 4：建立本次边界

整理本次目标、用户确认的测试目录、环境、允许的源码范围和明确排除项。环境名是否允许生成或执行统一由机械脚本判定，角色不得自行放宽脚本结论。

完成信号：只有通过严格结构校验的脱敏摘要、已确认项目画像、项目规则和当前项目内只读证据可以进入下一阶段；原始 HAR 始终留在脚本边界外。
