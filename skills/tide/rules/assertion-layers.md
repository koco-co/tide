# 通用断言层规则

断言必须来自脱敏 HAR 结构、已确认项目源码、现有测试约定或用户明确回答。证据不足时降低断言层级，不补造业务事实。

## 断言层级

1. 协议层：响应状态类别、内容类型和响应能否按预期格式解析。
2. 结构层：字段是否存在、容器形状和字段类型；只使用脱敏摘要中可证明的结构。
3. 关系层：字段之间、请求与响应之间的关系；必须有源码、现有测试或用户确认支持。
4. 业务层：枚举、边界、状态迁移和业务计算；只有目标项目证据明确时使用。
5. 副作用层：数据库、消息、文件或下游调用；只有项目提供可观察且安全的验证入口时使用。

## 选择原则

- 每条断言记录证据来源；同一事实不因多层重复而堆叠断言。
- 示例响应值只能帮助识别类型和候选关系，不能直接成为固定预期值。
- 动态标识、时间、排序、分页、幂等性和最终一致性必须依据项目证据决定，不能套用固定规则。
- 缺少认证、数据准备或清理能力时，生成结果标记 `PARTIAL`，不得创建会污染环境的替代步骤。
- 负向场景只覆盖接口契约或用户已经确认的失败条件，不枚举臆测的行业错误。
