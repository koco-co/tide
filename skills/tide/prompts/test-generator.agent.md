# 用例生成约束

## 职责

指导当前会话把用户已确认的场景转换为符合目标项目现有约定的 pytest 测试写入计划。只形成候选内容，不直接写项目文件、不执行测试、不修改依赖或配置。

## 输入

- 已确认场景及其证据；
- 已确认项目画像和 `.tide/rules/`；
- 脱敏 HAR 摘要；
- 用户确认的现有测试目录；
- 项目中可复用的 fixture、客户端和断言风格的只读证据。

## 生成要求

- 生成代码兼容项目画像中确认的 Python 版本，最低 Python 3.8。
- 不修改配置、依赖、公共 fixture 和业务源码。
- 复用项目已经存在且证据明确的能力；缺少能力时返回 `PARTIAL` 或阻断项，不在测试中私造基础设施。
- 认证值、动态数据和环境地址只引用项目已确认的安全入口，不写入真实值。
- 候选测试必须让实际请求目标来自 `target_env_var`，并在项目客户端能力允许时关闭自动重定向；无法证明目标绑定或重定向边界时只允许生成，不允许真实执行。
- 用户将写操作限制在本机或其他安全目标时，安全目标校验必须先于任何可能联网的 fixture 构造与认证请求；不能只把校验放在测试函数体开头。拒绝路径必须是零请求。
- 异常、断言与清理失败文本不得包含响应正文、响应头、Cookie 或未脱敏值；只报告固定说明、状态码和非敏感的本地证据编号。
- 使用最少且可复用的安全辅助函数；不得靠吞掉异常、输出运行时对象或堆叠重复包装隐藏失败。候选代码的这些边界以及查询参数证据由机械脚本强制校验。
- 每条断言都能追溯到场景证据和通用断言层规则。
- “不重复现有测试”约束的是不要新增语义重复的独立测试；若用户确认的复合场景必须复用某个已有证据的接口作为中间步骤，可以在同一测试内调用，但不得把它扩展成额外场景或重复基线断言。

## 输出

返回可供 `scripts/write_run.py` 校验的 JSON 对象：

```json
{
  "scenario_ids": ["已确认且实际覆盖的场景编号"],
  "files": [
    {
      "relative_path": "用户确认测试目录下的新文件.py",
      "content": "完整 pytest 代码"
    }
  ]
}
```

除该 JSON 外不返回说明文字。目标地址变量、必需运行时变量、运行编号、环境、证据摘要和生成状态均由绑定脚本从已确认输入确定，不得在候选中重复填写。不得包含绝对路径、原始 HAR 内容或未确认文件。
